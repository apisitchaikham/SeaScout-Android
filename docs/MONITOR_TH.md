# Sea Scout · ระบบเฝ้าดูสุขภาพระบบและแจ้งเตือน (r14.15.73)

ระบบตรวจตัวเองทุก 30 นาที โดยใช้ตัวตั้งเวลาเดิมของงานสินค้าอัตโนมัติ (ไม่เพิ่มตัวตั้งเวลาใหม่) และแสดงผลในหน้าแอดมิน แท็บ **"สุขภาพระบบ"**

## ตรวจอะไรบ้าง

| เรื่อง | เตือน 🟠 | ต้องแก้ 🔴 | ส่งอีเมล |
|---|---|---|---|
| คำขอ Worker ทั้งบัญชีวันนี้ (นับทั้งเว็บและ seascout-cache, โควตาฟรี 100,000/วัน) | ≥ 70% หรือคาดว่าทั้งวันจะเกิน | ≥ 90% | ตั้งแต่ 🟠 |
| D1 แถวที่อ่าน (5 ล้าน/วัน) และแถวที่เขียน (100,000/วัน) | ≥ 70% หรือคาดว่าจะเกิน | ≥ 90% | ตั้งแต่ 🟠 |
| คำขอที่ใช้ CPU เกินโควตา (Error 1102 เช่น ล็อกอินอีเมลหนักเกินไป) | ≥ 1 ครั้ง/วัน | ≥ 20 ครั้ง/วัน | ตั้งแต่ 🟠 |
| โค้ดเซิร์ฟเวอร์ผิดพลาด (Error 1101) | ≥ 10 ครั้ง/วัน | ≥ 50 ครั้ง/วัน | 🔴 |
| เซิร์ฟเวอร์ข้อมูลที่แอปใช้: seascout-cache, NOAA Tides, CoastWatch, OceanWatch, PacIOOS | ใช้ไม่ได้ 1 รอบ | ใช้ไม่ได้ 2 รอบติด (≥ 30 นาที) | 🔴 |
| แอปแครชหรือผิดพลาด (จาก /api/crash) | ≥ 30 ครั้ง/ชม. | ≥ 100 ครั้ง/ชม. | 🔴 |

- "วันนี้" นับตามเวลา UTC ซึ่งเป็นรอบเดียวกับที่ Cloudflare รีเซ็ตโควตา (07:00 น. เวลาไทย)
- อีเมลจะส่งเมื่อเริ่มมีปัญหา เมื่อปัญหาหนักขึ้น เมื่อยังไม่หายผ่านไป 12 ชั่วโมง และเมื่อกลับมาปกติ ปัญหาเดิมจะไม่ส่งซ้ำทุกรอบ
- รายงานแครชถูกนับรายชั่วโมงตามชนิดของข้อผิดพลาด ลิงก์และตัวเลขยาวในข้อความถูกรวบเป็นแบบเดียวกัน จึงนับบั๊กเดียวกันเป็นแถวเดียว ไม่เก็บ IP หรือข้อมูลผู้ใช้ และจำกัดจำนวน เพื่อไม่ให้แครชวนซ้ำกินโควตา D1
- ประวัติเก็บ 7 วัน (สุขภาพระบบ) และ 14 วัน (แครช) แล้วลบเอง
- ภาระต่อรอบ: คำขอออกไปข้างนอกไม่เกิน 7 ครั้ง, เขียน D1 ประมาณ 10 แถว (ประมาณ 500 แถวต่อวัน จากโควตา 100,000)

## ตั้งค่า (ทำเองใน Cloudflare, ห้ามใส่คีย์ลง git)

### 1. ตัวเลขการใช้งาน (แนะนำ)
1. Cloudflare → รูปโปรไฟล์ → **My Profile → API Tokens → Create Token → Custom token**
2. Permissions: **Account → Account Analytics → Read** (สิทธิ์อ่านอย่างเดียว ไม่ให้สิทธิ์อื่น)
3. Account Resources: เลือกบัญชีของคุณ แล้วกด Create แล้วคัดลอก token ไว้
4. Workers & Pages → **seascout** → Settings → Variables and Secrets → Add:
   - `CF_ANALYTICS_TOKEN` = token ที่ได้ (ชนิด **Secret**)
   - `CF_ACCOUNT_ID` = Account ID (ดูได้ที่หน้า Workers & Pages ด้านขวา, ชนิด Text)
5. เข้าหน้าแอดมิน → สุขภาพระบบ → กด **ตรวจตอนนี้**

### 2. อีเมลแจ้งเตือน (ถ้าต้องการ)
ต้องตั้งระบบอีเมล (Resend: `RESEND_API_KEY` + `EMAIL_FROM`) ไว้ก่อน แบบเดียวกับที่ใช้ส่งรหัสยืนยันอีเมล จากนั้นเพิ่ม:
- `ALERT_EMAIL` = อีเมลที่จะรับแจ้งเตือน (ชนิด Secret, ใส่ได้สูงสุด 3 อีเมล คั่นด้วย ,)

ถ้ายังไม่ตั้งอีเมล ระบบยังตรวจและแสดงผลในหน้าแอดมินตามปกติ

## ปิด/เปิด
หน้าแอดมิน → เปิด/ปิดฟังก์ชัน → `monitor` (เปิดอยู่ตั้งแต่ติดตั้ง)

## หมายเหตุเรื่องล็อกอินอีเมล
ระบบใช้ PBKDF2-SHA256 100,000 รอบ ซึ่งเป็นค่าสูงสุดที่ Workers รองรับ ทดสอบบนเว็บจริงวันที่ 21 พ.ย. 2026 แล้ว ผ่านทั้ง 4/4 ครั้ง ไม่มี Error 1102 จึงยังไม่ลดรอบ เพราะการลดรอบทำให้รหัสผ่านปลอดภัยน้อยลง ถ้าวันไหนแถว "CPU เกินโควตา" เริ่มขึ้น จะได้มีตัวเลขจริงไว้ตัดสินใจ
